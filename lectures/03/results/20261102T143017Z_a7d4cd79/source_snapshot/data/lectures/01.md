# 第1回 AIエンジニアリング概論と開発環境

## この回のねらい

- AIエンジニアリングが「モデルを作る」ことより「モデルを部品として使い、評価と改善を回す」ことに重心がある領域だと理解する
- 講座を通して使う開発環境（GitHub Codespaces、GitHub Copilot、Gemini API）を自分の手で動かせるようにする

## 要点

1. **AIエンジニアリングとは**：学習済みのLLMを部品として、データやツールとつなぎ、評価しながら改善して、役に立つシステムにする仕事。
2. **LLMの基本**：入力をトークンに分け、続きのトークンを予測して文章を作る。出力は確率的に揺れる（temperature）。知らないことも、もっともらしく答えてしまう（ハルシネーション）。
3. **APIで使う**：Gemini APIをPythonから呼び出す。APIキーは秘密情報なので、Codespaces secretに登録し、環境変数 GEMINI_API_KEY として読む。コードには書かない。
4. **開発環境**：Codespacesはrepoに書かれた設定（devcontainer）どおりの環境をクラウド上に作る。使い終わったら停止する。
5. **AIコーディング**：Copilotの補完やチャットでコードを書く。提案は読んで理解してから採用する。
6. **提出の流れ**：講座repoをfork → 回ごとの作業ブランチで作業 → lectures/NN/answer.md を書く → 自分のforkの main へPR。

## 演習で体験すること

- app/ask.py で素のLLMに質問し、講座に固有のことは知らない（「分からない」と答えるか、一般論で推測する）ことを確かめる（第3回でツールを持たせて改善する）
